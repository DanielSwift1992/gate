# Каталог форм правил (библиотека гейтов, не DSL)

Правило клиента переводится подбором формы из этого каталога. Каждая
форма — проверенный образец из корпуса; слева — как звучит правило у
клиента, справа — тип.

## 1. Равенство полей (внешний ключ / same-department)

«Доступ только внутри своего департамента», «запись ссылается на
существующую и согласованную».

    public enum VerifiedView<Who: Employee, Of: Doc>: Close
    where Who.Home == Of.Home {}

Нарушение = тип не существует. Прожито: V1–V4, W1; каскад при правке
данных — адреса вне диффа.

## 2. Ворота по рангу (набор возможностей)

«Только менеджер администрирует». Ранг конформит набору способностей,
гейт требует конформанс:

    extension Administer: Authorized
    where Who.Rank: CanAdmin, Who.Home == Of.Home { ... }

Нарушение = «'Carol.Rank' does not conform to protocol 'CanAdmin'».
Прожито: контрольная B2; обход поднятием ранга — W3 (пол: намерение).

## 3. Владелец (row-level право)

«Удаляет только владелец»:

    public enum Delete<Who: Employee, Of: Owned>
    where Of.Owner == Who, Who.Rank: CanAdmin {}

Прожито: контрольная B3 (новый Owned-док + Delete владельца).

## 4. Порог / неравенство через запас

«Не меньше N», «соотношение ≥ 9:2». Счёт не бывает отрицательным,
поэтому заявить запас = доказать неравенство:

    Legible<Bright, Dark, Slack>
    where Bright == Plus<Times<180, Dark>, Plus<57344, Slack>>

Прожито: 17 контраст-сертификатов палитры плейграунда. Любая
рациональная граница переносится этим приёмом.

## 5. Арифметический сертификат (суммы, балансы)

«Части складываются в целое», «7 + 20 = 27»:

    typealias TwoRoadsOneDrop = EnergySum<Whole, Left, Right>
    // судится арифметическим каноном: Plus-дерево → один нумерал

Прожито: решётка атома (этаж-вкладка), отказ именем сертификата.

## 6. Единственность / количество в списке

«Один грант на человека», «не больше двух менеджеров». Список сам по
себе НЕ судится (граница гейта, см. «чего не обещаем») — единственность
заявляется отдельной записью-сертификатом со счётом:
кандидат формы для перевода — счётная запись `Tally`/`count` с
равенством. Дыру этого сорта verify находит посевом duplicate-grant
(прожито: NOT TRANSLATED в демо). Если у клиента есть такое правило —
это первый кандидат на новую форму мира при переводе.

## 7. Переходы состояний (конечный автомат)

«Заявка из Draft уходит только в Review», «пин 4-2-4-2». Правило = тройка:

    enum Approve: SlotRule { Slot = TicketSlot; From = Draft; Into = Review }

Кнопка/действие = подстановка ровно одной строки. Прожито: Buttons/пин,
живой экран поляризаторов, электрон атома.

## 8. Чётность / шаг решётки

«Зазор всегда чётный», «уровень кратен шагу»:

    extension EvenGap where N.Gap == Twice<K> {}

Прожито: двухщелевая интерференция (чётность в записи зазора).

## Правила выбора формы

- Сначала ищи форму с равенством (1): большинство «правил» клиента —
  ссылочная согласованность.
- Возможности (2) — когда правило про «кто имеет право», а не «что с чем
  согласовано».
- Не изобретай форму под кейс: если правило не ложится ни в одну —
  это разговор с нами о новой форме мира, не самодеятельность энкодера
  (verify всё равно поймает расхождение вердиктов).
