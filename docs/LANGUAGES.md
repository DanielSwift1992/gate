# A source names its language

`Kind` chooses the installed reader. A row's `typealias Language = HarborLanguage` selects the `languages.HarborLanguage` context in `.gate/forms-definitions.json` format 2. It supplies exactly `namespace`, `definitions`, `imports` and `scope_map`. A context cannot set `profile`, `reader` or `court`. Repeated `languages`, context names or context fields refuse at their record address; a JSON decoder cannot discard a declaration to make the record hold. A declaration of another Swift module is data, not a new reader or a grant to execute it.

`definitions` names taken rows. Each import is `{module, inputs, namespace}`: its module name is literal, its nonempty inputs are taken rows, its namespace owns their file-scope declarations. Definitions and import inputs pass the same repository/revision/source_path/SHA-256 resolver as other inputs. Missing definitions, undeclared imports and conflicting symbols in one namespace name their addresses. Whole-module imports are supported; qualified import syntax is addressed unsupported. Availability is checked on the reader's parsed type expressions before equality: a delivered module with a missing declaration has an addressed residue, and an independent namespace can still be read. This is not a Swift body checker. Different Language contexts are judged separately; homonymous declarations do not join them. Qualified selection between homonymous imported namespaces is currently addressed `unsupported`, rather than flattened into one court stream. Unknown syntax never establishes `holds`. Swift page bodies are not compiled by this reader.

`scope_map` names one taken `CarriedFile`. Its bytes use vi's `vi-scope-map/1`; see the pinned owner's `Checks/Grammar/README.md`. The map replaces vi's default repository census. Every language source, including imported definitions, is covered using its original source path, never a local cache/view path. The longest component prefix wins; uncovered paths and conflicting equal prefixes refuse. One source identity and vi law revision cannot have two byte-distinct maps. Identical references combine. The record contains a row reference, never a second distribution of scopes.

`bin/grammar-law.from` records the owner's revision and hashes of its portable scope reader and compiler-derived grant census. These three carried files in `bin/grammar-law/` are checked by the builder before being compiled into the binary. They contain no showcase paths. They are updated together from vi, not edited as a gate dialect. The compiler pin of a world's definitions and the judge's `bin/gate-judge.from` stay independent of this grammar-law pin.

`GET /grammar-contexts` gives the same context plan used by status and live serve judgement: record digest, law revision/census digest, original source identities, source hashes, map hashes and selected scopes. It does not grant capabilities or choose a reader. `tests/grammar-contexts.py` runs N2 on an ordinary external Git fixture, including a declared fourth module and negative controls; `tests/smoke.py` runs it in the battery. Its optional `--vi-tools ... --vi-theory ... --evidence ...` also compares the actual typed mirror with that plan on the same source/map bytes.

The released worlds' partial v2 record has no `Language` axes and a null `scope_map`. Its existing serve path remains until migration 4a supplies their complete contexts. It is not full publication/1. Once a scope map or Language is declared, an incomplete context is refused; it cannot fall back to the old union of definitions. The NoDrawing/ReadOnly publication builder resolves prepared Language contexts into its common ReadPlan, including declared contexts, the resolved receipt and each input’s Language and origin. Serve and static delivery carry those same snapshots; neither transport reruns a private context resolver. Source-relative local identities keep relocation from changing the semantic plan. Reader drafts, Drawing publication and migration of every old world are later slices.
