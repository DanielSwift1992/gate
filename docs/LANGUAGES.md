# A source names its language

`Kind` chooses the installed reader. A row's `typealias Language = HarborLanguage` selects the `languages.HarborLanguage` context in `.gate/forms-definitions.json` format 2. The original context supplies `namespace`, `definitions`, `imports` and `scope_map`. The source context additionally supplies explicit `module` and `intrinsics`; declaring either requires both. Its optional `receipts` field is a list of taken row references. A context cannot set `profile`, `reader` or `court`. Repeated `languages`, context names or context fields refuse at their record address; a JSON decoder cannot discard a declaration to make the record hold. A declaration of another Swift module is data, not a new reader or a grant to execute it.

`definitions` names taken rows. Each import is `{module, inputs, namespace}`: its module name is literal, its nonempty inputs are taken rows, its namespace owns their file-scope declarations. Definitions and import inputs pass the same repository/revision/source_path/SHA-256 resolver as other inputs. Missing definitions, undeclared imports and conflicting symbols in one namespace name their addresses. Whole-module imports are supported; qualified import syntax is addressed unsupported. Availability is checked on the reader's parsed type expressions before equality: a delivered module with a missing declaration has an addressed residue, and an independent namespace can still be read. This is not a Swift body checker. Different Language contexts are judged separately; homonymous declarations do not join them. The source context translates each original file into `vi.court.context/2`: module selects an import, namespace owns declarations, and role identifies an own or borrowed source. Every field carries its record or manifest address. Gate never inserts Swift exports, source aliases or imports. Declared `vi.court.intrinsic-swift/2` is closed to Never and String; the Court validates it. Qualified nested names are resolved by the same owner notation reader for where and count. Unknown syntax never establishes `holds`. Swift page bodies are not compiled by this reader.

`scope_map` names one taken `CarriedFile`. Its bytes use vi's `vi-scope-map/1`; see the pinned owner's `Checks/Grammar/README.md`. The map replaces vi's default repository census. Every language source, including imported definitions, is covered using its original source path, never a local cache/view path. The longest component prefix wins; uncovered paths and conflicting equal prefixes refuse. One source identity and vi law revision cannot have two byte-distinct maps. Identical references combine. The record contains a row reference, never a second distribution of scopes.

`bin/grammar-law.from` records the owner's revision and hashes of its portable scope reader and compiler-derived grant census. These three carried files in `bin/grammar-law/` are checked by the builder before being compiled into the binary. They contain no showcase paths. They are updated together from vi, not edited as a gate dialect. The compiler pin of a world's definitions and the judge's `bin/gate-judge.from` stay independent of this grammar-law pin.

`GET /grammar-contexts` gives the same context plan used by status and live serve judgement: record digest, law revision/census digest, original source identities, source hashes, map hashes and selected scopes. It does not grant capabilities or choose a reader. `tests/grammar-contexts.py` runs N2 on an ordinary external Git fixture, including a declared fourth module and negative controls; `tests/smoke.py` runs it in the battery. Its optional `--vi-tools ... --vi-theory ... --evidence ...` also compares the actual typed mirror with that plan on the same source/map bytes.

A context with module/intrinsics asks the Court for `vi.court.sources/1`. Where covers each own FormsFile or DocumentFile separately; definitions and imported files remain borrowed. Count covers all presented sources. WorldFile keeps the company reader, and CarriedFile does not acquire an autonomous judgement by naming Language. Scope coverage still applies to every declared language source. The complete named original files and context travel through the common ReadPlan; no source concatenation or gate-created name table precedes the owner reader.

For a DocumentFile, the explicit Court `--document` request uses the owner's DefinitionView. Executable value bodies are disclosed as unchecked at their original addresses. Their original bytes still reach Drawing. No checked application means empty. DefinitionView does not hide count-rule bodies from validation, and changing Kind cannot discard negative declarations. Legacy contexts retain their previous DocumentReaderV1 boundary until explicitly migrated.

A `receipts` reference must name a taken text CarriedFile. Its verified v2 bytes have schema `gate.court.receipts/1` and a `receipts` array of `gate.court.receipt/1` entries: request_sha256 and response (exit, stdout, stderr). The hash covers original named source and context bytes, question/options, pinned reader revision, grammar policy revision/hash and each source's scope identity/map digest. Gate checks the exact response input roster, per-source coverage and outcome/count consistency before reuse. Provenance identifies the owner; the owner's check must independently recompute these receipts with the pinned Swift Court. A hash by itself does not establish an answer. Inline answers inside Language are refused. A broken declared receipt input refuses; changed request bytes use a fresh Court reading.

Serve and static snapshots carry the same resolved request/receipt plan. A changed browser source is re-read for imports and PredicateReading selectors by the wasm notation owner port; grammar is checked against the pinned compiler-exported policy. The grammar transport currently declines non-ASCII identifiers outside its compared subset. Newly added questions are judged, removed questions are retired, and errors from unchanged inputs or record fields remain. Heavy changed questions run in a worker; an unchanged complete request can reuse its pinned owner receipt. Process caches hold only freshly computed answers keyed by the entire request, never a path or a previous green state. The latest parsed context can also be reused after resolving pins and hashing the complete manifest, record and delivered row bytes again; a changed or lost source invalidates it. File-opened pages give the worker the same carried glue and wasm bytes through a Blob instead of fetching a neighbour.

The bench receives the declared DocumentFile roots in `/files.documents`; Drawing uses their declared dependency closure in `/files.drawing_inputs`, with no filename exclusions. `/files.world_files` keeps the separate company selection. Neither set is inferred by subtracting another set. Missing document input refuses the drawing read; adding, dropping or editing a source loses exact Drawing comparison.

A manifest row can declare `typealias DrawingInputs = AnotherRow` or a tuple of distinct row names. Drawing reads the transitive closure from all `DocumentFile` rows, in path order, without changing a dependency's Kind. Missing or ambiguous rows, repeated references, duplicate axes, cycles and unsupported expressions are addressed refusals. The same closure is used by serve and static snapshots. The owner Drawing case must name this same set.
