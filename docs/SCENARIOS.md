# Пользовательские сценарии (каждый шаг стоит на глаголе; дыры названы)

Метод: сценарий рвётся там, где шагу нет глагола/поверхности. Найденные
дыры либо закрыты кодом (помечено ✦), либо в регистре неточностей.
Прожитые шаги помечены ✓.

## Персоны

- **Оценивающий** — узнал, хочет пощупать за 10 минут, ничего не подписывая.
- **Владелец мира** (платформенный/SRE) — внедряет, держит CI и правила.
- **Исполнитель тикета** (разработчик или LLM-агент клиента) — меняет факты.
- **Ревьюер PR** — решает merge; после гейта его вопрос — намерение.
- **Аудитор** (нетехнический) — читает отчёт, требует доказательств.
- **Владелец политики** — меняет правила (редко, громко).

## S1 · Первое касание (оценивающий, ~10 минут, локально)

Узнал (витрина/статья) → `gate init` → скопировал свой экспорт →
перевёл СВОИМ агентом по AGENT.md (или руками в CSV) → `gate import` →
находки строками своих файлов ✓ (grants.csv:6 · 7 ms) → решение.
Ничего не отправлял, ничего не подписывал.
Дыра (в очередь): готовых адаптеров реальных форматов (Okta/AD/K8s) нет —
CSV-мостик руками или агентом.

## S2 · Онбординг домена (владелец мира, ~день)

`init` в своём репо → import → **чистка базы** (первые находки — до
любых разговоров с нами ✓ verify сам останавливается на грязной базе и
называет строки) → `verify --against <легаси>` — карта перевода правил ✓
(4 covered + 1 NOT TRANSLATED) → без легаси: `verify` без --against ✦ —
самопроверка «какие правила вообще держат» ✓ (5 посевов: 4 held by the
world, 1 NO GATE — дубль-грант) → hook + CI из скелета → команде
объявлены три команды из README.

## S3 · Тикет «выдай доступ» (исполнитель, минуты) ✦

`gate check view WHO DOC` — мгновенный ответ ✓ → если refused: адрес и
пара имён — ответ в тикет копипастой → если легально:
`gate diff grant WHO DOC` ✓ → `gate apply grant WHO DOC` (пишет только
на holds) → PR; CI зелёный по построению.
Прожито: кросс-грант refused с парой имён; дубль-грант holds — известный
пол, ловится verify-посевом (S2).

## S4 · Тикет «переведи сотрудника» (исполнитель) ✦

`gate diff transfer WHO DEPT` → механика (ростер + командная запись)
делается сама; **view-гранты не переносятся автоматически — это
намерение**, ответ называет каждый остаток адресом ✓ (ровно 1 остаток:
старый view) → решение человека: `apply revoke` старого + `apply grant`
нового (или оставить и объяснить) → `apply transfer` → PR.
Это продуктизация W1: то, что ревью искало минутами, тут — штатный
ответ за миллисекунды.

## S5 · PR-ревью мира (ревьюер)

PR меняет tables/ или world.swift → CI-гейт: красный = адреса строками
CSV (exit-код ✓) → ревьюер читает git-дифф таблиц (человекочитаем
бесплатно) → его единственный вопрос — намерение (W3-класс: «а должен
ли был?»). Согласованность уже снята гейтом — измерено этажом 0.

## S6 · Квартальный аудит (аудитор, без терминала)

Владелец: `gate report -o q3.html` ✓ → один самодостаточный файл
письмом → аудитор читает таблицы и вердикт → вопросы «кто и когда» —
`git log/blame` по tables/ (история мира бесплатно: мир живёт в git).
Recertification: список грантов = таблица report; отзыв = S7.

## S7 · Инцидент «протухший грант» (SRE) ✦

`gate status` — находка с адресом ✓ → `gate diff revoke WHO DOC` ✓
(holds после отзыва) → `apply revoke` → PR → CI зелёный.
Либо то же в верстаке: карточка → клик → правка → Save ✓.

## S8 · Изменение правила (владелец политики, редко и громко)

Правка нормативного слоя → компилятор зелёный, вторая запись расходится
и называет строку (W2 ✓: build 4.5 s зелёный / судья 18 ms красный) →
согласованная двойная правка в двух кодировках + человеческое ревью
диффа политики (пол PP15 — заявлен).
Дыра уровня продукта (известна): у клиентского мира пока фикс-набор
правил образца; свои правила = новые формы (этаж 2, K8s RBAC).

## S9 · LLM-агент как исполнитель (агент клиента)

Тикет → агент: check → diff → apply → PR с вердиктом в описании.
Всё через CLI (JSON + exit-коды ✓) или serve (read-only) — применение
только через CLI/PR сознательно. AGENT.md учит переводу ✓ (мини-этаж-2:
чужой sonnet перевёл, заметил протухший грант, судить отказался).
MCP-обёртка — очередь (тонкая, поверх тех же JSON).

## S10 · Масштаб

Судья линеен: 200 записей — 18–28 ms; 12 800 персон / 136k строк —
~150–200 ms (замер плейграунда, та же механика). Enterprise-снапшот
судится быстрее, чем открывается его тикет.

## Дыры, закрытые этим документом ✦

- `grant` / `revoke` — не было глаголов самого частого сценария (S3, S7).
- `transfer` не делал механику (командная запись) — теперь механика
  автоматически, намерение (view) — остатком с адресами (S4).
- `verify` требовал легаси — теперь --self-режим (S2).

## Дыры в очереди (не закрыты, названы)

- Адаптеры реальных форматов экспорта (S1) — пока CSV-мостик.
- Свои правила клиента = новые формы (S8, этаж 2).
- MCP-обёртка для агентов (S9).
- report: строка «источник истории — git» (S6, мелочь).
