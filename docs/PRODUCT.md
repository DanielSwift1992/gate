# Gate — граница продукта (спека v0, 2026-07-20)

Один инструмент, один мир, одна граница. Без DSL, без промежуточных
записей, без «совместимости» с чужими формами правил.

## Мир (что внутри)

Переведённая часть системы — один Swift-текст двух слоёв:
- **Нормативный слой** (правила): типовые гейты с `where` — как
  Policy.swift/Filtering.swift в образце. Пишется один раз при переводе.
  Мал: 3 гейта на 204 записи в образце, ~десятки строк.
- **Слой фактов** (записи): плоские декларации-факты — как
  GeneratedTeam.swift. Генерируется механически из ваших данных.

Внутри мира правила простые и не обсуждаются:
- один факт — одна запись; связь двух фактов — условие равенства в типе;
- рассогласование невыразимо: такой файл не собирается, отказ приходит
  адресом и парой имён;
- ничего не исполняется: проверка — чтение; переведённый слой не имеет
  рантайма, версии зависимостей ему безразличны, дрейфовать нечему.

Два арбитра, всегда оба: компилятор (полная проверка, секунды) и
линейный судья (тот же вердикт по фрагменту фактов, миллисекунды).
Расхождение арбитров — сигнал само по себе («закон подвинули»).

## Граница (что снаружи, API)

Снаружи — ваша система в привычной вам форме. Она не переписывается.
Она разговаривает с миром тремя глаголами:

1. **ask** — вопрос к фактам: «может ли X читать Y?», «встанет ли эта
   запись?». Ответ = попытка записать факт + суд: `holds` или `refused`
   с адресом и именами. Миллисекунды. Чтение, ничего не меняет.
2. **change** — изменение: перевод, найм, выдача доступа — в привычной
   форме (флаги/JSON). Инструмент сам пишет дифф файла, судит и отвечает:
   `applied` или `refused` со списком ВСЕХ записей, которые изменение
   ломает (включая записи за сотни строк от диффа). По умолчанию dry-run.
3. **import** — механический перевод ваших ФАКТОВ (CSV/JSON) в слой
   фактов. Данные — не DSL: ваша таблица переводится как есть.

Правила через API не меняются. Правка нормативного слоя — всегда дифф
Swift-файла под ревью человека: это не ограничение инструмента, это его
смысл (ревью сжимается до диффа политики).

## Конвейер захвата (как пылесосим пространство клиента)

**Три сорта клиентского пространства, по убыванию механичности:**
1. **Таблицы (факты)**: реестры, матрицы доступов, конфигурация,
   инвентарь. Переводятся механически: колонка = ось, строка = запись,
   уникальные значения = атомы пула (Next-кольца). `import` это делает.
2. **Правила-условия**: то, что у клиента живёт в IAM-ролях,
   SoD-матрицах, if-ах сервиса. Переводятся один раз руками ИЗ КАТАЛОГА
   готовых форм (не DSL — библиотека типовых гейтов): равенство полей
   (Home==Home), ранг-ворота (Rank: CanAdmin), владелец (Owner==Who),
   порог/неравенство через запас (паттерн Legible), чётность/шаг.
3. **Код-вычисления**: переводится НЕ алгоритм, а его инвариант-сертификат
   — суммы (7+20=27 судится арифметическим каноном), пороги, переходы
   состояний (конечный автомат = тройки Slot/From/Into). Императивный код
   с эффектами не переводится: не наш клин, граница твёрдая.

**Путей входа много — дверь одна.** Адаптеры читают форму клиента как
есть (CSV/JSON/SQL-дамп/экспорт IdP); печатает мир всегда один генератор
слоя фактов. Никакого промежуточного языка, который клиенту нужно учить.

**Два режима жизни, лестница внедрения:**
- **Зеркало** (вход): истина у клиента, мы регулярно снимаем снапшот →
  печатаем мир → судим → отказы приходят СТРОКАМИ ЕГО ЖЕ ФАЙЛОВ
  (проверено: `grants.csv:6 · Engineering against Finance`, 7 ms на
  снапшот). Read-only аудит, нулевой риск внедрения, ценность с первого
  прогона: протухшие гранты по адресам.
- **Истина** (цель): мир становится источником; изменения идут через
  `change` (адресный отказ до записи), клиентские системы читают `ask`
  или экспорт. Переход зеркало→истина — по доверию, домен за доменом.

Каждая ступень полезна сама: факты без правил уже судятся на висячие
ссылки; каждое переведённое правило втягивает следующий пласт.

## Переход (лёгкий — и из чего он состоит)

- Факты: `import` — механика, минуты.
- Правила: перевод руками, один раз. Это единственная настоящая работа
  (E2.5: вся сложность в энкодере), и она мала, потому что нормативный
  слой мал. Цену не прячем: она и есть цена входа, зато одноразовая.
- Часть системы: переводится один домен (например, доступы). Остальное
  живёт как жило и спрашивает по API.

## Почва (стратегия роста)

Git — стихийно открытая индустрией v=i для байтов: проверка = опознание
хеша, рассогласование ссылки невыразимо. Поэтому каждый git-репозиторий
планеты — уже развёрнутый узел нашей системы: транспорт, идентичность,
история, хостинг, PR-процесс и привычки готовы. Мы не строим платформу —
мы прорастаем в существующей: отдаём git усиления (bisect, merge-страж,
журнал) и растём через его вездесущность. Ни одного нового протокола.

## Опыт-цель (что пользователь хочет на самом деле)

Формула: **«как git»**. Шесть свойств, каждое — критерий приёмки:
1. **Не думать**: класс проблем исчез, а не «появился инструмент борьбы».
   О страже вспоминают в момент поимки; в норме он невидим.
2. **Пять секунд до понимания в отказе**: строка моего файла, два имени,
   что сделать.
3. **Свои инструменты**: git, редактор, CI, агент. Ноль новых мест.
4. **Попробовать без разрешения**: локально, на копии, выкинуть.
5. **Доверять без веры**: любой ответ пересуживается на месте за 20 ms.
6. **Гордиться артефактами**: зелёный чек, report, журнал — то, что
   показывают друг другу.

Бесшовность (сделано, прожито demo-seamless/): мир находится подъёмом по
дереву, как .git — работает из любого подкаталога, без env и путей;
**канон источника (перевёрнут осознанно)**: world.swift — ЕДИНСТВЕННЫЙ
источник всегда, читабельный всем (git diff, человек, судья, компилятор);
tables/ — вход для первой печати (bootstrap) и зеркальных снапшотов,
никогда не перекрывают мир; таблица — ВИД (export/Table по запросу),
не хранимая правда. `git diff` от нас — всегда дифф Swift-файла. Вывод human-строками по умолчанию, `--json` — машинам (как
porcelain-флаги git). `init` внутри git-репо сам включает pre-commit
(core.hooksPath). Проба в check носит имя реального мира.

## Как это объяснять (питч-ход: git-прецедент)

Жанр не нужно доказывать с нуля — индустрия его уже приняла, это git.
Коммиты и деревья — факты, адресуемые содержимым; ссылка — хеш; тихо
подменить факт нельзя — ссылка не сойдётся; `git fsck` — судья. Git дал
эту гарантию коду, и ей доверяют все. Справочники, доступы и тарифы тех
же команд живут «как до git»: копии в трёх системах, тихий дрейф, ручной
аудит. Формула: «вашему коду вы это уже дали — это git; мы даём то же
вашим фактам». Git — не цель перевода (код не наш клин), git — прецедент.

**Архитектурно мы устроены как git, и это закон продукта:** интерфейс =
глаголы над одной формой; глагол либо оставляет мир зелёным, либо не
применяется (`change --apply` пишет только на holds — как commit не
создаёт битую ссылку); руками править можно (plumbing), но суд неизбежен.
Соответствия: init↔init · commit↔change --apply · fsck↔judge/status ·
diff↔адресные отказы+export · log↔git log репо клиента (история миру
достаётся бесплатно: мир живёт в git). Дистрибуция тоже его: git победил
формой «локально, бесплатно, свой репозиторий, без сервера» — сервисы
выросли потом поверх формы; наш «без веса» — та же траектория.

**Тандем: gate усиливает git (каждый пункт — слепота git, закрытая
судьёй; первые два прожиты демо demo-tandem/):**
1. **Semantic bisect**: судья за 20 ms — предикат `git bisect run` →
   git сам находит коммит, внёсший рассогласование. Прожито: обход
   гейта («move Priya per reorg», правка руками мимо хука) найден
   автоматически, ноль лишних шагов.
2. **Пара bisect+blame закрывает глубину 2**: строка отказа ≠ строка
   причины; blame по адресу судьи даёт происхождение записи-жертвы
   (прожито: показал initial commit), bisect — коммит-причину. Порознь
   git-археология на глубине 2 слепа.
3. **Merge-страж**: текстуально чистый, семантически битый merge (два
   зелёных PR, вместе красные) — judge на merge-результате в CI; вековая
   слепота построчного слияния.
4. **Ветки = what-if миры фактов**: реорг-план — веткой, суд на каждой,
   merge по решению. У данных впервые появляется ветвление.
5. **PR-процесс для данных**: изменение фактов получает обсуждение,
   ревью и гейт — data governance из git-коробки.
6. **Журнал аудита бесплатно**: `git log` по грантам = журнал выдач с
   авторами и датами (прожито); signed commits = подписанные выдачи;
   tag = зафиксированный квартальный аудит.
7. **Revert под судом**: откат, ломающий сегодняшний смысл, ловится до
   применения.

Категория тандема: GitOps для бизнес-фактов. «Git for data» давал
историю и дифф без судьи смысла; GitOps дал «истина в git» для
инфраструктуры. Наш тандем = истина в git + смысл, судимый статически
до merge. Судья — недостающая половина «git for data».

**Git-объекты как атомы: политика самого репозитория (`gate guard`,
прожито).** Автор коммита, ветка, пути — факты мира: автор HEAD через
tables/identities.csv становится персоной, требование действия — строкой
tables/guard.csv (action,requires_rank), суд — пробой СУЩЕСТВУЮЩЕЙ формы
(VerifiedAtRank). Branch protection и CODEOWNERS-класс переезжают из UI
платформы (копия правды вне репо) в таблицы самого репо. Прожиты три
исхода: неизвестная личность → refused («an unknown identity performs no
guarded action»), Manager → holds 1.1 ms, IC → refused парой имён.
Иерархия точек вшивания — модель власти git: **локальный хук =
вежливость** (обходится, но судит на месте — прожито: коммит таблиц
прошёл через собственный хук), **required check в CI = закон** (красным
не смержить), **Action = транспорт вердикта, не носитель правил** —
правила живут в таблицах мира, workflow лишь запускает `gate guard`.
Identity-маппинг — сам судимый факт. Богаче (области путей → свои гейты,
подписи) — рост форм, этаж 2.

**Read-доступ и клонирование (граница честности):** у git-протокола нет
ACL на clone — это слой транспорта/хостинга (прецедент: gitolite — ACL
поверх ssh с конфигом в git-репо). Мы read-контроль не исполняем: мы —
источник правды о том, кому положено; конфиг платформы (GitHub teams,
gitolite.conf) — печатаемый из мира артефакт, дрейф платформы против
мира — судимая сверка зеркального режима. Enforcement у платформы,
истина у нас.

**Ещё боли git, которые закрывает слой смысла:** lockfile против
манифестов и версии в монорепо (рассогласование файлов внутри репо —
наш жанр буквально); «текстуально бесконфликтный, семантически дубль»
мерж; долгоживущие ветки, тихо разошедшиеся смыслом (status на ветке за
миллисекунды); merge queue как институт — очередь существует из-за
CI-минут на проверку, судья схлопывает её (числа ниже).

**Кристалл домена (зрелость, обмен, измерение — `gate library`).**
У домена существует один канонический кристалл форм (SAT5); мир клиента
— его подмножество. Продукт этим пользуется тремя способами:
- **Стадии зрелости домена** — метрика, не маркетинг: растущий (формы
  прибавляются) → насыщенный (порог дискретен, PiR M8) → «домен закрыт:
  N форм» — публичный клейм с чекером (жанр B9). Покрытие меряется
  посевами: `library` печатает по каждому посеву held / no gate.
- **Обмен кристаллами**: `library diff` — set-операции; union безопасен
  по построению (Theorem 2), разность = «чему научить» (прожито:
  клиентскому миру teachable ровно Granted+View/Administer/Delete).
  Передаются ФОРМЫ, никогда факты — приватность по построению. Каждый
  переведённый домен обогащает общий каталог: сетевой эффект без сети.
- **Кросс-доменные зависимости** — пересечение кристаллов разных
  доменов (общие атомы/оси/формы, §5.18): «ваши IAM и HR делят 5 осей —
  вот судимые связи между ними».

**Метрики текут из суда сами (считаются, не помнятся):** размер мира
(декларации), связность (лукапы, премисы), здоровье (отказы = 0), цена
(миллисекунды) — `gate status` печатает их каждой строкой; git добавляет
время: churn фактов (log), MTTR рассогласования (bisect: родилось →
починено), журнал выдач по авторам. Метрика покрытия правил — verify
(--self: посевы, которые никто не держит).

**Пропускная способность мержа — посчитана бенчем (мир 2000 персон,
~10 000 записей-фактов):**
- полный цикл мержа (процесс + проба + суд + запись): **139 ms → 7.2
  мержей/с → ~26 000 мержей/час** одной последовательной очередью;
- чистый суд: 106 ms (оверхед глагола ~33 ms — почти вся цена и есть суд);
- против типичного CI-гейта (5–30 мин → 2–12 мержей/час на очередь):
  рост **×2 000–10 000**;
- одновременные писатели (люди и агенты, цикл «изменение в минуту»):
  устойчиво без роста очереди ≈ throughput × 60 — **~430 на мире 2000**,
  ~1200 на мире 200, ~240 на гиганте 12 800 (суд ~200 ms, замер
  плейграунда). Судья линеен ⇒ шардинг по доменам умножает.
- Потолок без инкрементальности: каждый мерж — ПОЛНЫЙ пересуд мира.
  Инкрементальный суд и параллельный мерж независимых диффов теперь
  стоят на ТОЧНОЙ теореме (MiC1–MiC4, статья merge_is_commutation в
  ядре v=i, 95014c7), не на оценке: независимость = ДВА дизъюнктных
  пересечения (изменённые записи И затронутые законы, включая
  принесённые диффом); конфликт мержа — не «провал», а перечислимое
  множество адресов. Реализация — механизация MiC4, по потребности.

**Предмет гарантии — другой, и в нём продукт:** git держит целостность
ХРАНЕНИЯ (адресат существует и не подменён — но закоммитит любой мусор,
нормативного слоя нет; hooks/protection/боты — рантайм рядом с формой,
policy-engine-жанр). Мы держим целостность СМЫСЛА: запись судится
правилом. Подмена у git ломается криптографически (хеш), у нас логически
(равенство осей): наша версия видит смысл связи; согласованная двойная
правка у нас легальна — заявленный пол (PP15), у git тут сильнее.
Самая короткая формула: gate — это fsck для смысла; историю миру даёт
сам git.

## Выгоды (каждая — из измеренного, private/etazh0/report.md)

- Вопрос к фактам: миллисекунды, ответ с адресом (18–28 ms на 200
  записях; плоско по размеру диффа).
- Изменение: полный пересуд всех связей на каждое изменение; каскадные
  поломки называются адресами вне диффа (W1: 2 записи за сотни строк).
- Ревью человека сжимается: согласованность забирает гейт (ревью-минуты
  → миллисекунды), человеку остаётся дифф политики и вопрос намерения.
- Ослабление правила не проходит тихо: вторая запись расходится и
  называет строку (W2: build зелёный, судья красный).
- Корректные изменения не трутся: 5/5 контрольных прошли с первой
  попытки (M3 = 0).

## Что мы заменяем (велью = что станет не нужно, и мы это знаем)

1. **Ручной аудит доступов** (квартальные recertification-таблицы руками)
   → `status`/`report` за миллисекунды, находки строками файлов клиента.
2. **Класс код-ревью на согласованность** (сопоставление полей за сотни
   строк) → судья. Измерено этажом 0: минуты и ~185k токенов сильного
   ревью → 27 ms; дешёвый тир на этом классе вообще слеп. Ревью остаётся
   намерению.
3. **Policy-engine рядом с системой** (OPA/Rego/Cedar: вторая копия
   правды + рантайм-оценка на каждый запрос) → политика внутри формы,
   `check` — чтение.
4. **Синхронизаторы копий** (cron-скрипты «сверить HR с IAM») → одна
   запись; расходиться нечему. Вторая запись, где она есть, — сигнал
   (W2), не копия.
5. **Тесты-инварианты на данные** (пины count'ов, ассерты единственности)
   → сертификаты в типе; дыры перевода находит `verify` посевом.
6. **Валидационные скрипты в CI** → один бинарь, exit-code, адреса.
7. **Отчёты-снимки для аудиторов** (вики-страницы доступов, устаревшие с
   рождения) → `report`: таблица не хранится, а печатается из мира.

Не заменяем (по-прежнему вслух): ревью намерения, рантайм-исполнение,
произвольный код.

## Экосистема (форма продукта вокруг бинаря)

- **CLI первичен** — он везде: терминал, CI, скрипты, и главное —
  LLM-агенты живут в CLI. Porcelain git-словаря (см. закон выше):
  init · status/fsck · check · diff · apply · import/export · verify.
  Красный вердикт = ненулевой exit: хуки и CI работают без обвязки.
- **git-хуки из коробки**: `gate init` кладёт `.githooks/pre-commit`
  (мир обязан держаться до коммита) — одна строка конфига у клиента.
- **UI — печатаемый, не серверный**: git выиграл без UI; интерактивные
  обёртки пришли потом от сообщества. Наш UI v0 — `gate report`: один
  самодостаточный HTML (таблицы мира + вердикт с адресами), печатается
  из мира, не хранится, прикладывается к аудиту письмом. Интерактивный
  UI — только при явном спросе, и тоже поверх формы, не вместо.
- **Локальный порт для IDE/редакторов**: `gate serve` — read-only
  JSON-поверхность на 127.0.0.1 (/status, /check/view, /diff/transfer).
  Изменяющих маршрутов нет сознательно: apply — руками или CLI.
  Deeplink-схему не делаем: localhost-URL покрывает те же сценарии без
  регистрации в ОС.
- **Доктрина чистой базы сквозная**: на грязном мире `check` честно
  отвечает refused фоном («сначала почини») — как verify.
- Очередь поверхностей: LSP (диагностики прямо на world.swift/CSV в
  редакторе — правильная конечная форма IDE-интеграции), MCP-сервер
  (gate как штатный тул LLM-агентов в IDE) — обе поверх тех же
  JSON-глаголов, тонкие обёртки.

## Нет своего save (закон замыкания в git)

У gate нет собственного канала персистентности: ни базы, ни стейта, ни
save. Всякое изменение — правил и фактов одинаково — это правка РАБОЧЕЙ
КОПИИ файлов-источников в репозитории клиента; историю, авторство, откат
и review ведёт сам git: commit (хук судит — вежливость) → PR → required
check (закон). Изменение правил — дифф нормативного слоя в PR, громкий по
построению (W2).

Следствия, закрытые кодом (после переворота канона):
- `apply` правит МИР — единственный источник; никакая печать его молча
  не перезатирает (bootstrap-печать — только когда мира ещё нет; новые
  CSV вливаются только явным `gate import`). Тест канона в батарее:
  «no second truth: CSV edit does not reprint the world»;
- хук и CI СУДЯТ мир (`gate status`), никогда не перепечатывают его —
  перепечатка в хуке была бы тем же save-мимо-источника;
- Save верстака легален всегда: мир и есть источник, суд неизбежен;
- единственный не переносимый клоном хвост — git config hooksPath
  (свойство git, не наше): строка повторной настройки стоит в README
  скелета.

## UX: три вопроса пользователя (дизайн-модель, зафиксирована)

Один бинарь везде: Swift линкуется статически (Linux/Windows-тулчейны
официальные) — конечная форма: CLI на Swift, судья внутри библиотекой;
один файл, как git, без его обвязки. (Очередь «CLI→Swift» = дорога сюда.)

**DSL не нужен — он уже есть, и это Swift.** Запрещён был ЧУЖОЙ язык
правил (вторая правда). «Минимальный, выразительный, то же самое» — это
ГОЛАЯ ФОРМА: ровно те декларации, что судья читает, минус церемонии.
Правило: пользователь пишет только различия, печать достраивает форму
(`Prod: Realm` → `public enum Prod: Realm {}`; упоминание в позиции
конформанса рождает протокол само). У голой формы НЕТ своего парсера —
она печатается в полный Swift, судит тот же судья; переход на «настоящий
Swift» = открыть напечатанный world.swift рядом. Прецеденты уже в деле:
CSV→мир, guard.csv→правило, rbac.json→жанр.

Три вопроса и три правила:
1. **«Что у меня уже есть?»** — полка: git-атомы из коробки (Author,
   Commit, Branch, File, Namespace — мир git уже описан нашими
   правилами), формы каталога, атомы своего мира. Одна команда — весь
   словарь (расширение library builtin-разделом).
2. **«Как использовать своё?»** — три входа, все данными: таблицы
   (факты), голые декларации (атомы/правила), строки распознавателей
   (вхождения). Хранение — наша кухня по дефолту (мир печатается);
   дробление своими файлами поверх — дверь, не обязанность (судья
   принимает список файлов).
3. **«Где что ищется?»** — скоупами, жёстко: атом объявляется ВНЕ
   скоупов, вхождения ищутся ТОЛЬКО в объявленных скоупах («ник в
   commit.message — да, в jira.log — нет» = есть строка / нет строки).
   Builtin-скоупы git из коробки. Дефолт без строки — не ищем: тишина
   лучше шума, шум подрывает доверие к отказам.

**Определения: прошиты, извлекаемы, приземляемы (`gate stdlib`, прожито).**
Бинарь не имеет зависимостей — канонические определения зашиты в него
Swift-текстами: git-атомы (Identity, Scope-атомы, GitPlace), жанры доменов
(genre-grants — общий с rbac-адаптером). Правило «скрыто ≠ тайное» (модель
git: упаковано, но cat-file покажет всё): `stdlib` — полка, `show` —
печать любого определения вплоть до всего, `materialize` — файл ложится в
репо клиента (с этого момента версионируется его git, импортируется его
кодом). Владение честное: нетронутая копия сторожится от дрейфа против
прошивки («re-materialize, or remove the header to own the file»),
снятая шапка = файл стал пользовательским. Полный v=i не вендорится (он
публичен; build-judge.sh пинует) — материализуется сабсет по запросу.

**Раскладка хранения — факт мира (`world.manifest.swift`, прожито).**
Дефолт — один файл, ноль церемоний. Хочешь дробить — объявляешь файлы
File-атомами в манифесте (typeName-литерал = путь), и мы ПОДЧИНЯЕМСЯ:
суд идёт по объявленному списку (кросс-файловый: леджер в одном файле
судится против ростера в другом — прожито, 158 премис через границу),
стражи держат оба направления — объявленный файл существует, соседний
*.swift объявлен («a shadow outside the judged list»). Жанр — прожитый
манифест плейграунда. File-атом — тот же, что в git-мире: раскладка
стыкуется с guard («нормативный слой живёт в policy.swift, менять может
только владелец» — CODEOWNERS-класс как судимая декларация). Управление
системой = правка мира, тем же PR, тем же судом. Очередь: маршрутизация
apply/print по Holds-оси манифеста.

**Дифф — двухвидовой (дизайн, реализация проекции в очереди):** дефолтный
`gate diff` показывает изменение в ГОЛОЙ ПРОЕКЦИИ (сокращённый Swift —
только различия, без церемоний), `--full` — полный текст; `git diff` —
всегда полный Swift. Проекция — вид над одним источником, не второй файл.

## Атомы: пространство имён истины (три слоя, все — данные)

Дисциплина (урок deps-эскиза): судья не парсит источники — судья судит
формы; читают адаптеры и распознаватели. «Читать можно что угодно,
судить всё будет один судья».

1. **Объявление**: атом рождается один раз записью в мире. Источник —
   таблица import, каталог, или СНАПШОТ внешней системы (Jira-экспорт →
   таблица тасков, тем же путём, что HR-JSON). Живость внешних систем =
   зеркальный режим: суд на снапшоте, дрейф — находка. Без демонов.
2. **Вхождение**: атом упоминается где угодно — код, комментарии,
   сообщения коммитов, ветки, доки. Распознаватель = строка таблицы
   (зона, паттерн, тип); извлечённые вхождения печатаются
   записями-ссылками, судья лукапит: вхождение без атома = «resolves to
   nothing» с адресом. Dangling-жанр на всё дерево.
3. **Связь**: кросс-системная эквивалентность = alias-мост
   (JIRA_123 = CheckoutV2Flag) — базовая форма мира; судима с обоих
   концов, оси гейтуются.

Строгость слоями: mention-карта мягкая по умолчанию (шум распознавания
реален), законом становится включённое клиентом («мерж требует открытый
таск» — строка guard.csv; «флаг без живого таска — отказ» — форма).

Применения-маяки: жизненный цикл фича-флагов (таск закрыт ⇒ флаг обязан
умереть — судимо на двух снапшотах); сквозной человек (git-автор =
Jira-assignee = владелец сервиса: оффбординг-аудит одним status по трём
системам — W1-каскад кросс-системно); переименование (все хвосты
старого имени адресами); верстак показывает атом со ВСЕМИ вхождениями —
объект и его ткань целиком.

Итог сдвига: мир — не «таблицы рядом с кодом», а пространство имён
истины клиента: каждый значимый объект объявлен один раз, всё остальное
— судимые ссылки. Ткань замыкается по объектам, не по файлам.

**Мир как бэкенд истины: фронтенды и статусы.** Все системы клиента —
фронтенды одного мира, в обе стороны:
- **Вход (менять статус из любого места), лестница гарантий**: зеркало —
  внешняя система меняет у себя, суд снапшота пост-фактум (изменить без
  нас можно, скрыть нельзя: дрейф именуется) → вежливость — плагин
  спрашивает `check` перед изменением (serve готов; плагины НЕ наши —
  наш артефакт только контракт поверхности) → закон — статус меняется
  через `change`→PR, required check держит.
- **Записи в чужих зонах — судимые, не исполняемые**: тело таски — зона
  распознавателя; `typealias CheckoutV2Flag = Dead` в таске миграции —
  записанное обещание, сверяемое судом с реальностью кода на каждом
  снапшоте. Неудалённый флаг — именованный отказ, не чья-то память.
- **Тотальность реестра**: объект не исчезает — у него меняется
  статус-ось (явная запись; история в git append-only). Table-срез по
  типу атома полон по определению: «все фича-флаги» — одна таблица,
  читаемая, не хранимая.
- **Выход (объект-360)**: отношения объекта читаются из любого фронтенда
  (виджет в тикете → read-поверхность): атом со всеми вхождениями и
  связями — гранты, коммиты, флаги, владения, упоминания.

## Лестница ценности (что пассивно при подключении, что растёт при переводе)

Продукт — тулза для работы с самим git: правила настраиваются в нём же,
таблицами в репо. CI/CD не переделываем и не отрисовываем — это лишний
вес; наш след в CI — одна строка required check.

**t0 — подключение (ноль перевода, ноль настройки), read-only:**
- **Незаписанные связи из собственной истории** (co-change): «A и B
  меняются вместе N раз из M» — точная статистика, не похожесть.
  ПРОВЕРЕНО на своём репо: вслепую найдены ВСЕ настоящие связи
  (index↔screenshot 97% — правило, жившее только в прозе дисциплины;
  артефакт↔источник сборки 100%; движки↔страница 91–100%), ложных в
  топе нет. Каждая пара — кандидат «записать связь формой или хуком»:
  t0 сам показывает, куда переводить.
- **Идентичность**: список авторов/emails, разнобой, доля подписанных
  коммитов — точные факты, подготовка guard.
- **Покрытие ткани = 0%** — честная точка отсчёта метрики.
- НЕ обещаем в t0: суда (судить нечего) и лок-чекеров (нативные тулзы
  экосистем уже есть — не наш вход; эскиз guard deps это подтвердил:
  вертикаль без читателя осей дала ложный holds — снят).

**t0+ε — 15 минут, два CSV:** `guard merge` — первый ЗАКОН (политика
мержа в репо) без перевода единого факта данных.

**t1 — первая таблица переведена:** status/check/diff/apply по ней,
отказы строками своих файлов, hook+CI, report аудитору.

**t2 — связи записаны:** каскады transfer видимы (адреса вне диффа),
verify против легаси, перекрёстные суды таблиц.

**t3 — насыщение (кристалл):** library/зрелость/«домен закрыт», и
уникальные свойства поиска — судимые запросы, невозможные до перевода:
check любой пары за мс, what-if диффом, semantic bisect по истории,
срезы Table. Поиск — награда перевода, не обещание входа.

Каждая ступень тянет следующую: co-change (t0) называет место для t1;
guard (t0+ε) приучает к закону; первая таблица (t1) делает видимой цену
второй.

## Верстак мира (UI, выросший из системы, — построен)

`gate ui` (страница на `gate serve`): слева мир как код, справа вердикт
и таблицы. Жанр — **gitk-класс, не IDE общего назначения**: верстак
открывает ТОЛЬКО мир (world.swift), не проект клиента — смешанный проект
остаётся в его редакторе, наш верстак — «быстро посмотреть и поправить
факт». Прожито циклом: открыл → refuses 1 карточкой со строкой → правка
в редакторе → holds на клавише (суд ~2–6 ms в браузере) → Save →
бинарный судья на диске подтверждает.

Почему это UI «бесплатно и без компромисса»:
- **Судья в браузере — ТОТ ЖЕ судья**: judge.js — дословный порт
  Tools/Judge.swift, паритет запечатан золотыми векторами плейграунда.
  Не «вторая реализация для UI», а та же вторая запись.
- **Swift у клиента не нужен**: рендерер и судья уже существуют в JS
  (байт-паритет). DocumentKit — зависимость НАШЕЙ сборки, не клиента.
  Вопрос «делать ли DocumentKit зависимостью» снят: он уже отвязан
  портом.
- **Таблицы читаются из судимых деклараций** (Code/Table плейграунда):
  не хранятся, перерисовываются на каждый суд.
- Save подтверждается ответом сервера (не только состоянием кнопки).

Регистр неточностей (сигналы временного дизайна, направление названо):
- gate.py читает мир регексами (world_rows/report), верстак — судимыми
  декларациями. Две читалки одного мира. Направление: одна читалка —
  таблицы отдаёт судья (бинарь учится `--tables` или report печатается
  верстаком), report становится печатью той же поверхности.
- Верстак v0 — textarea без подсветки; полный редактор (CodeMirror,
  инспектор, completion) уже существует в плейграунде — переезд его
  оболочки на «мир из URL» = верстак v1. Не делать, пока v0 не упрётся.

## Чего не обещаем (вслух, с примерами)

- Намерение: тихое повышение ранга легально в типах (W3) — вопрос
  «а должен ли был» остаётся человеку, и после перевода это единственный
  его вопрос.
- Членство в ненормированных списках и другие незаявленные связи —
  не судятся, пока не заявлены типом.
- Соответствие правил вашему намерению: гейт держит записанное правило,
  не задуманное.

## Перевод без доверия (почему нам не нужен вес)

Кто переводит — безразлично: клиентский инженер, sonnet, любая модель.
Переводчик снаружи мира и не является частью продукта. Проверяем перевод,
не переводчика:
- **Факты**: round-trip — мир печатает таблицы обратно (`export`), diff с
  исходником клиента пуст. Прожито: import → export → diff пуст байтово.
- **Правила**: дифференциально — посеянные нарушения (методика этажа 0)
  отказываются и старой системой клиента, и миром; расхождение вердиктов =
  адрес непереведённого правила.
Опора: AI6 — при обёртке «генератор + гейт» ложный зелёный невозможен при
любом качестве генератора. Поэтому мы не бюро переводов и не LLM-сервис:
мы владеем формами, судьёй и сверкой — статической инфраструктурой.
Операционного веса (пайплайны, обслуживание перевода) не набираем.

## Не делаем (граница твёрдая)

- Не переводим произвольный код (клин — политика над фактами, не
  тотализация программ).
- Не читаем чужие формы правил (Rego/Cedar/YAML): каждая совместимость —
  вторая копия правды и рантайм-оценщик. Вы либо переводите правило в
  мир, либо оно остаётся вашим.
- Не прогибаем мир под кейс: мир маленький, правила его фиксированы.

## Форма и дистрибуция (что делает это продуктом)

Продукт = один бинарь + три файла в карманах, которые у клиента уже есть.
Мы не хостим ничего.

- **Артефакт**: один статический бинарь `gate` (release-сборка; судья
  внутри, пять глаголов). Единственное, что мы собираем и подписываем.
- **Карман 1 — git клиента**: `gate init` рождает мир В ЕГО репозитории:
  tables/*.csv (его данные, никуда не уходят — для доступов это довод
  номер один), README с тремя командами, world.swift печатается из
  таблиц. Приватность = свойство формы, не обещание.
- **Карман 2 — его CI**: .github/workflows/gate.yml из пяти строк —
  каждый PR к таблицам судится, отказ = красный чек строкой его CSV.
  Плечо B эксперимента, ставшее продуктом.
