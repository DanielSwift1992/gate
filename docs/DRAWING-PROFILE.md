# A profile is read at its owner

The owner reads its palette with Swift DocumentKit. In showcase the command is `./drawing-profile`: it emits `drawing.css` and `receipt.json`. Its check repeats that reading and compares the bytes. Gate takes those outputs as declared inputs, checks their hashes against the actual source inputs, and carries them through serve and publish. Publishing a profile needs no Python, Node or Swift on the receiving machine.

`Publication.DrawingProfile` names a pinned Theirs `DrawingProfileFile`, or `NoDrawing`. The file is a `drawing-profile/1` JSON receipt. `reader` names its ID, version and source hashes. `profile_row` names the source profile metadata, `palette_row` its palette, and `inputs` binds every selected row by SHA-256. `css` names the CSS row and its hash. `contract_row` names the Drawing input, or is null for an explicitly empty Contract. The source profile, explicit bindings, palette, font, metrics, license, contract and CSS remain ordinary declared rows. The receipt must name exactly the source profile's inputs; filenames and family labels select no special path.

`result` contains the owner's bindings, witnesses, font measurements and resources. Gate supports the measurement profile in `bin/drawing-fonts.json`. Intact measurements outside that profile give addressed unsupported. A missing input or license, stale input set, false SourceFontSHA256 or changed delivery hash gives refused. A refused publish leaves the previous output untouched. The CSS, font, license and owner receipt use shared content addresses; a font is delivered once.

Drawing contract acceptance is the byte receipt in `bin/drawing-contract.from`. Another well-delivered candidate remains an input and yields not-compared, a reason, null contract_pin and zero cases. A damaged contract input refuses. The actual Drawing comparison also binds its current source bytes and the installed port; neither a relation's holds nor an owner-resolved palette compares an arbitrary canvas with Swift.

A publication's palette and structure are read-only. Change them at the source, ask the owner to read them, then publish the new receipt. A MINE palette in an editable live serve can use the existing browser port: its caption says that the owner receipt is stale. That port does not author a replacement owner receipt or write an unsaved source to disk.

The battery's A3/A4 inputs are transformations declared by the owner in `Profiles/Playground/Controls/variants.json`. `tests/owner-profile.py` checks out the exact showcase publication pin into a temporary directory and runs its `Checks/profile-inputs.py --export <scratch>`. Swift DocumentKit reads the current transformed inputs and checks receipt digests before the test gives those temporary bytes to the isolated binary. This adds an owner SwiftPM build to the development test; it adds no tool to a gate installation and stores no second palette or full control receipt. The owner's build law also changes a palette value outside either transformation and requires both variants and their digests to follow that edit.
