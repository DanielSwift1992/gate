# Boundary law and pinned owner

`python3 tests/dependency-boundary.py` consumes the owner implementation and shared counterexamples declared by `bin/boundary-law.from`: repository, full commit and SHA-256 for each file. The implementation lives in vi. The local wrapper supplies CONFIG (`tests/dependency-boundary.json`), POLICY_SHA256 and the checked root. It verifies the pinned bytes before execution; missing or corrupt inputs refuse with their pin address. A verified cache is an input cache, not a second maintained implementation. `python3 bin/boundary-owner.py` acquires the exact public commit. For an unpublished reviewed commit, `--repository LOCAL_GIT` explicitly acquires committed bytes from that repository; it never reads its worktree or silently falls back to a neighbor. Publication requires the declared commit to be available publicly.

The policy lists source scope, lexical selectors, exact declarations and a shrinking debt ledger. It covers implementation, tests, manifests, examples, demo materials and documentation. Common words Team, Remote, Document, Verified, Person and Lead are matched only in subject forms (including subject CSV) or standard-library paths. Other declared names also match associated-type bounds, case lists and parameter labels; named departments, ranks and workplaces match literals and CSV. OnSite, Sexed and Ranked are globally selected. Named behavior selectors also hold existing table discovery, ring construction, field mapping, routes, command dispatch, demo selection, manifest forms and verb bindings. Removing a noun does not remove a still-matched behavior. This remains a finite lexical vocabulary; it cannot infer the semantics of arbitrary new identifiers or obfuscated code.

Every debt row names its removing task in the data. Exact declarations distinguish navigation without behavior, frozen inputs and explicitly pinned inputs. Public command recipes that promise subject behavior are debt. Existing fixture exemptions have exact paths and reasons; no whole directory or newly self-labelled reference is exempt. Non-NUL input must decode as UTF-8 or refuse with an address. NUL-containing bodies are not source text; their filenames still participate.

The source ceiling is the policy's frozen Git revision. Every historical policy also limits all occurrences it recognized, across all reachable merge parents. A reviewed extension may first recognize old frozen source; it cannot restore an occurrence retired under an earlier selector. Exact reviewed references may be reclassified as debt. Shallow history refuses; `git fetch --unshallow` obtains the missing history explicitly. Rewriting or discarding accepted history changes the law itself.

Remove a debt row when its source occurrence is removed. For address-only movement use `python3 tests/dependency-boundary.py --refresh-addresses`; it never creates an exception. If an approved declaration changes, review its meaning and exact row, then use `python3 tests/dependency-boundary.py --policy-digest` and place the resulting candidate seal in the wrapper's POLICY_SHA256. This command only prints a digest: it does not approve or edit the policy. Rerun the law and controls after review. SHA-1/SHA-256 values inside an otherwise unchanged source line are opaque to this lexical identity; input contracts separately verify their bytes.

`python3 tests/dependency-boundary-controls.py` runs the owner's shared counterexamples with this policy, including real changed bytes, ordinary prose, declaration contexts, invalid encoding, debt removal, declaration review, moved addresses, source-ceiling growth, real Git retirement/restoration, policy extension and shallow history. The ordinary battery runs the law and controls and preserves their addressed refusals.
